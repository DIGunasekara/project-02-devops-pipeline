Project Success Criteria
Phase 01 — Planning and Requirements

System architecture is documented.

Frontend, backend, chatbot and database responsibilities are defined.

Functional, DevOps, security and non-functional requirements are documented.

All seven milestones are documented.

Each milestone has a clear completion target and deliverables.

Acceptance criteria are defined for milestone completion.

Phase 02 — Infrastructure

Rocky Linux VM is updated and accessible.

Required tools are installed and verified.

SSH access and firewall rules are reviewed.

Unnecessary network ports are closed.

Phase 03 — Git Workflow

Source code is stored in GitHub.

Feature branches and pull requests are used.

Changes are reviewed before merging.

Branch protection is configured where supported by the repository plan.

Phase 04 — Application and Containers

Frontend, backend and chatbot work as expected.

Backend can access the database.

Docker Compose starts all required services.

Application data survives container recreation.

Health checks and application logs are available.

Phase 05 — CI/CD

Automated tests execute on pull requests.

Container images build successfully.

Images are published to a registry.

Staging deployment is automated.

Production-like release requires appropriate validation and approval.

Phase 06 — Operations

Monitoring and health alerts are tested.

Backups run according to the documented schedule.

A backup can be restored successfully.

Deployment rollback is tested.

Operational procedures are documented.

Final Acceptance

The project is accepted when all required milestones have evidence of completion, the application can be deployed through the documented pipeline, and the recovery procedure has been verified.
